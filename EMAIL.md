# Email — support@aurapharma.us

How the Aura Pharma mailbox is set up, where its DNS lives, and how the site's account emails (Supabase) send from it.

> **This repo is public.** No passwords, app passwords or recovery details here.

*Set up 2026-10-17.*

---

## The mailbox

| | |
|---|---|
| Provider | **Zoho Mail**, plan **Mail Lite (5 GB)**: $1/user/month billed annually, **$12/year** for one user |
| Address | `support@aurapharma.us` (display name "Aura Pharma") |
| Read mail | https://mail.zoho.com, or the Zoho Mail app (iOS / Android) |
| Admin console | https://mailadmin.zoho.com (users, aliases, domain, DKIM) |
| Data centre | US |

Google Workspace and Microsoft 365 were tried first; both blocked the sign-up ("unusual activity"), so we went with Zoho.

**Aliases** (e.g. `orders@`, `noreply@`) are free on Mail Lite and deliver to the same inbox: mailadmin → Users → the user → Email aliases.

**Sending limit:** Mail Lite allows a few hundred outgoing emails a day. Fine for support and account emails; for order emails at volume, move automated mail to a transactional service (Zoho ZeptoMail, Resend, Postmark) and keep this mailbox for people.

## DNS (Cloudflare)

aurapharma.us DNS is on Cloudflare. The Zoho records were added with Zoho's one-click "Log in to my DNS" (Domain Connect).

| Type | Name | Value | Priority |
|---|---|---|---|
| MX | `@` | `mx.zoho.com` | 10 |
| MX | `@` | `mx2.zoho.com` | 20 |
| MX | `@` | `mx3.zoho.com` | 50 |
| TXT | `@` | `v=spf1 include:_spf.google.com include:zohomail.com ~all` (SPF) | — |
| TXT | `zmail._domainkey` | `v=DKIM1; k=rsa; p=…` (DKIM, generated by Zoho) | — |
| TXT | `@` | `zoho-verification=…` (domain ownership) | — |

- Keep **one** SPF record only. The `_spf.google.com` part is left over from the Google Workspace attempt; it's harmless and can be removed.
- Don't turn on Cloudflare Email Routing: it would replace the Zoho MX records.
- Not set yet: a DMARC record (`_dmarc` TXT, e.g. `v=DMARC1; p=none; rua=mailto:support@aurapharma.us`). Add once mail has been flowing cleanly for a while.

Check the records from any machine:

```
nslookup -type=mx aurapharma.us
nslookup -type=txt aurapharma.us
nslookup -type=txt zmail._domainkey.aurapharma.us
```

## Other mail apps (IMAP / SMTP)

| | Server | Port |
|---|---|---|
| Incoming (IMAP) | `imappro.zoho.com` | 993, SSL |
| Incoming (POP) | `poppro.zoho.com` | 995, SSL |
| Outgoing (SMTP) | `smtppro.zoho.com` | 465 SSL, or 587 TLS |

Username is the full address. Use a Zoho **app password** (accounts.zoho.com → Security → App Passwords), not the login password.

## Supabase account emails (sign-up confirmation, password reset)

Supabase dashboard → Authentication → Emails → **SMTP Settings** → Enable Custom SMTP:

| Field | Value |
|---|---|
| Sender email | `support@aurapharma.us` (or a Zoho alias such as `noreply@aurapharma.us`) |
| Sender name | `Aura Pharma` |
| Host | `smtppro.zoho.com` |
| Port | `465` |
| Username | `support@aurapharma.us` |
| Password | a Zoho app password named "Supabase" (never commit it) |

Then:

1. Authentication → **Rate Limits**: Supabase drops to about 30 emails/hour once custom SMTP is on; raise it if sign-ups need more.
2. Authentication → Emails → **Templates**: edit Confirm signup, Reset password, Magic link etc. to say Aura Pharma.
3. Test: create an account on https://www.aurapharma.us with a fresh address; the email should come from "Aura Pharma <support@aurapharma.us>". Check spam on the first few.

The sender email must be the Zoho mailbox or one of its aliases, or Zoho rejects the mail.
